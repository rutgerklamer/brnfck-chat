Watch it run

The form “Divide by 2ᵏ, round, clamp to −128…127” works on 12 cells; the named ones are “X” and “result”. Press Play, drag the step slider forwards and back, or change shift k and X with the sliders:

Dividing by 2ᵏ means: throw away the k lowest bits. The bit peel reads the bits one by one, so it can simply not write the low ones.

Rounding is free: add half of 2ᵏ before the division. Negative numbers are free too: add a fixed offset first so that everything is positive, and take it off the result.

The limits are checked without comparing. A second copy of the number has every peeled bit taken off again. If that copy is not zero at the end, the number was outside the range, and only then are the high bits looked at to see on which side.

What it needs

  • Cells that wrap at a known width. The program text is made for that width (8, 16 or 32 bits) and gives wrong answers on any other.
  • To be fast it needs an interpreter that does a flat loop in one step. In plain steps the shifts are long loops and the gain is lost.
  • Ten scratch cells. The input is used up. The true value must fit the cell, and k + 8 must be less than the cell width.
Common mistakes
  • Letting the sum wrap before it is clamped. A clamp cannot repair a number that has already gone round.
  • Using this for a divisor that is not a power of two. For that the project multiplies by a reciprocal from a table first (see table lookup as a decision tree).
