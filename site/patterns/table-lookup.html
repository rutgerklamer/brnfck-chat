Table lookup as a decision tree

Gives entry number x of a fixed table, in a number of steps that depends on the size of the table and not on x.

Watch it run

The form “A table of squares” works on 11 cells; the named ones are “x” and “y”. Press Play, drag the step slider forwards and back, or change x with the slider and edit the choice of entries:

The table is not on the tape. It is in the program text, as a tree of if and else: first "is bit 0 of x set?", inside each answer "is bit 1 set?", and so on. At the end of each path one entry is added to the result.

The questions are the tests of the bit peel, so no bit is ever stored. A table of 256 entries is 8 questions deep: about 70 steps.

The price is length. Every entry has its own path in the text. The table of 16 squares here is about 4,000 characters; with 256 entries it is 134,000.

What it needs

  • Cells that wrap at a known width. The program text is made for that width (8, 16 or 32 bits) and gives wrong answers on any other.
  • To be fast it needs an interpreter that does a flat loop in one step. In plain steps the shifts are long loops and the gain is lost.
  • Nine scratch cells. The table length is a power of two. An x past the end counts from the start again.
Common mistakes
  • Using it for a big table. The text grows with the table; the tape form, store and fetch by index, does not.
  • Using a tree where x is nearly always tiny. A chain of "take 1 off, still not zero?" is shorter and then just as fast: that is the form The naive way: a chain on this page.
