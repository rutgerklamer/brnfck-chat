The bit peel

Reads a number bit by bit, at a fixed cost per bit, instead of counting it down unit by unit.

Watch it run

The form “Eight bits of a number” works on 16 cells; the named ones are “x”, “bit 0”, “bit 1”, “bit 2”, “bit 3”, “bit 4”, “bit 5”, “bit 6” and “bit 7”. Press Play, drag the step slider forwards and back, or change x with the slider:

On a cell that wraps, multiplying by 2 pushes the top bit out of the cell. Multiply by enough twos and only one bit of the number is left inside: the cell is non-zero exactly when that bit is set.

And multiplying is a flat loop: one step. So "is bit j set?" becomes a question brainfuck can ask, at a cost that does not depend on the number.

The peel asks it for the lowest bit first. If the bit is set, it is taken off the number, so that the next test sees one bit again. Eight bits take 23 to 56 optimised steps: 23 when one bit is set, 56 when all eight are. The size of the number does not come into it.

Everything on the advanced pages is "peel some bits and do something for each set bit".

What it needs

  • Cells that wrap at a known width. The program text is made for that width (8, 16 or 32 bits) and gives wrong answers on any other.
  • To be fast it needs an interpreter that does a flat loop in one step. In plain steps the shifts are long loops and the gain is lost.
  • Six scratch cells, zero before and after. The number is used up.
Common mistakes
  • Running the 8-bit text on 16-bit cells: the bits no longer fall out where the text expects.
  • Peeling from the top bit down. The low bits must be gone first, or the test sees several bits at once.
