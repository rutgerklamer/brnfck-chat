Watch it run

The form “A product and a rest” works on 2 cells, named “n” and “scratch”. Press Play, drag the step slider forwards and back, or change n with the slider:

One + adds one. For a large number that is a long text, so we let a loop do the adding: a rounds of b make a × b, and a few more + or − fix the rest.

The loop needs a counter, so it costs one scratch cell. The text is then about 2 × √n characters long instead of n.

For really large numbers (wide cells) the number is written in base 256: each byte is made small and shifted up by a loop that multiplies by 256.

What it needs

  • The target cell must be zero before, or the constant is added to what is there.
  • The loop forms need one scratch cell that is zero, and leave it zero.
  • The "wrap" form needs 8-bit wrapping cells. It gives a different number on any other size.
Common mistakes
  • Using a short form from a table of constants without checking the cell size it was made for.
  • Counting characters only. On an optimising interpreter every form here is one to three steps; in plain steps the loop form is slower than the long row of plus signs.

Where it is used

  • Print a constant string is this pattern, once per letter.
  • Brainfuck basics, lesson 5, "Building numbers", builds a number as a product. Build toward a chatbot, lesson 3, "Multiplying by a fixed number", does it for a big number, and Build toward a chatbot, lesson 8, "Size", shows why the length of the text matters for the chat program.
