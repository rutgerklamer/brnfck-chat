Notice how little there was to write. The plan came first: cell 1 holds the character to print, and cell 2 counts the rounds. With that written down the loop nearly writes itself: <.+>−

Deciding what every cell is for, before you type a single command, is the most useful habit in brainfuck. Keep the eight symbols out of the words of the plan. (The program you started from had an empty loop, which never ends. The machine stops any run after 200,000 steps.)

A plan in words

Now the plan is three lines above the box, and the program is yours. Write a program that reads one digit and prints that many stars: 3 gives ***. It is tried with 3, 0 and 9:

Notice that the program has three parts, one for each line of the plan. Each is something you have done before: taking 48 off in Lesson 8, building a number in Lesson 5, and a loop that counts down in Lesson 4. They are joined by an agreement about the cells.

Test each part before you write the next: the tape under the box shows whether part 1 really left the number, and not 48 too many. For the input 0 the last loop never starts, and nothing is printed. You did not have to do anything for that edge. It came with the loop.

Notice that you wrote about fifty commands from one sentence: plan the cells, build a part, test it, build the next.

Nothing larger works differently. A brainfuck program that chats is the same thing, hundreds of millions of commands long, and no person typed those: a program wrote them, part by part, with an agreement about the cells.

What you can do now

You can write a small program from a description: plan the cells, build it in parts, test each part, and try the edges.

The programs of A plan in words and On your own come back as the challenges That many stars and Count down from, where your program is also measured: how many commands, how many steps.

Programs are read as often as they are written. Lesson 10 is about reading brainfuck that somebody else wrote.
