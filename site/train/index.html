Trained in brainfuck

The chat programs on this site run models that were trained elsewhere, on graphics cards. brnfck-train-names-bigram-756, brnfck-train-names-mlp-7k and brnfck-train-names-attn-10k learn themselves. Each starts from random numbers, reads a list of 1,402 names through its comma command, and learns from it, one step after another: it guesses the next letter, measures how wrong it was, and moves every weight a little. When it is done, it prints a second brainfuck program, its child, which holds what it learned and makes up new names. Another kind prints itself, with what it learned written in, so that the next program trains on. brnfck-train-shakespeare-attn-55k, larger, learned Shakespeare overnight.

Train one here

Pick a program and press Train. Your browser builds the training program from its generator, which takes a fraction of a second, and runs it in the same brainfuck runtime as the chatbot. The program reads the names, twenty times over in a new order each time for the two larger ones, 32 letters per step. After every step it prints its loss: how surprised it was by those 32 letters, in nats. Each line it prints is checked against the line the plain JavaScript version of the same training printed.

Three networks

All three learn the same thing: given the letters of a name so far, the next letter, or the end of the name. They differ in how far back they look.

brnfck-names-bigram-756
Looks one letter back. A table of 27 by 27 numbers: for every letter, how likely each next letter is. 756 weights, 902 steps.
brnfck-names-mlp-7k
Looks three letters back. 64 hidden units each add up a number for each of the three letters, squash the sum with tanh, and pass it on to the 27 possible next letters. 7,003 weights, 6,018 steps.
brnfck-names-attn-10k
The same, plus one attention head over the last eight letters. The newest letter asks a question (a query of 16 numbers); every earlier position offers a key and a value; the dot products of the query with the keys, through a softmax, say how much of each value to take. 10,251 weights.

Training is the same loop for all three, 32 letters per step: for every letter, run the network forward, compute the loss, and go back through the network to find out how each weight should change (backpropagation). After 32 letters, move every weight, with momentum: each weight keeps 7/8 of its last move.

Learning in whole numbers

A brainfuck cell holds a whole number, here of 32 bits. So every number of the training is a whole number with an agreed scale: a weight of 0.25 is stored as 4096, in 16384ths. The tanh, the exponential of the softmax, 1 divided by a sum and the logarithm of the loss come from tables. Every division is a shift with a fixed way of rounding. The learning rate is a shift too: the error of each guess is divided by a power of two before it goes back through the network, 16 in the two larger programs.

Because nothing in it is a floating-point number, there is nothing to round differently on another computer. Any brainfuck interpreter with 32-bit cells, on any machine, ends with the same weights, to the last bit. That is also how the programs are checked: a plain JavaScript version of the same arithmetic must print the same lines and end with the same numbers.

The tape is laid out for brainfuck's one way of reaching memory, moving left and right. Each hidden unit has a frame of cells with all its weights, 145 slots of 13 cells for the attention program. The forward pass walks from frame to frame with one shared piece of code, carrying the letters and the sums along. The backward pass walks back.

Where the attention looks

Type the start of a name. The attention head of brnfck-names-attn-10k weighs the last eight letters, and the bars show how much of each it takes in to guess the next letter. Nobody told it where to look: it found out during training. It often looks at the first letters of the name, which say much about how it goes on.

Names they made up

Each child program prints 30 names, drawn letter by letter with its own random numbers. The more a network sees of a name, the more the names it makes up sound like names. Names that are in the list it learned from are marked.

It prints its next generation

Brainfuck has no files, and nothing on the tape outlives the run. A program that has learned something can keep it only one way: by printing it, as a new program. The training programs above print a child that can only make up names. A second kind prints itself: the same training program, with the weights it ended with, their momentum, its step count and the last letters it read written into it. Run that program on more names and it trains on from where the last one stopped, then prints the next. A generation that is fed nothing prints the child.

Below, brnfck-train-names-bigram-756 in 20 generations: each trains on a twentieth of the names and prints the next. The table is read from the programs themselves. Every generation, fed nothing, prints a child, and the child holds each weight as a run of + or −.

What a generation is made of, here gen1 and gen2 of brnfck-train-names-attn-10k, to scale. Most of it is the body written out as data: that is what lets the body print itself, character for character, behind the new weights.

How it was checked

node tools/train.js builds the three training programs, runs each through the WebAssembly runtime on the names, and compares it with compiler/train/reference.js, the same training in plain JavaScript whole numbers:

  • every line it prints, the loss of each step, equals the line of the reference: 902, 6,018 and 6,018 lines;
  • every weight and every velocity on its tape at the end equals the reference: 841, 7,287 and 10,749 slots;
  • the child program it prints equals, character for character, the one the reference writes from its own weights;
  • the child, run on its own, prints the same 30 names as the reference.

That shows the program does what the reference does. That the reference learns the right thing was checked against a version of the attention network in floating point: for each group of weights, the change the whole-number training makes points the same way as the true gradient, with a cosine of 0.9996 or more and a size within 4%. Each building block of the programs, from multiplying two cells to printing a number, is tested on its own in compiler/train/test-kernels.js.

Shakespeare, overnight

The same kind of network, made larger, learned Shakespeare. brnfck-shakespeare-attn-55k looks at the last 16 characters with its attention and at the last 4 with 128 hidden units, and has 54,513 weights. Its training program, 29 million characters of brainfuck, read the plays of Tiny Shakespeare through its comma command on one core of a home computer, in passes of a million characters, about three quarters of an hour each. It learns from the first 90% of the text. The last 10% it never reads; that part measures how well it does on text it has not seen. What each pass wrote

After every pass the training program printed its child: a second brainfuck program of about 12 million characters, the weights as runs of plus and minus, then an engine that writes 40 lines. Pass 0 is the child of the random weights it started from.

Run a child here

Your browser builds the child of the pass above from its weights, compiles the brainfuck to WebAssembly and runs it. With seed 1021 and 40 lines it is the program the training printed, and it must write the same text, character for character. Any other seed draws other characters from the same chances.

Where it looks

Notes and sources

  • The code: compiler/train/ (spec.js the scales and tables, reference.js the training in JavaScript, kernels.js the building blocks, layout.js the tape, gen.js the programs) and tools/train.js. The page uses site/train/lib.js, made from them by tools/site-train.js, which also writes the recorded data in site/train/data/.
  • The names: compiler/train/data/names.txt, a list of 1,402 first names written for this project.
  • On Hugging Face: the four training programs in bf/, the programs they printed in bf/children/, the training programs that print their next generation in bf/generations/, and the whole Shakespeare run, every pass and its child, in runs/brnfck-shakespeare-attn-55k/.
  • The networks follow the character-level name models of Andrej Karpathy's makemore (a bigram table, the multilayer network of Bengio et al. 2003, attention as in Vaswani et al. 2017), made to fit 32-bit whole numbers.
