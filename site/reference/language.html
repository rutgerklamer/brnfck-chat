The language, precisely

A brainfuck program works on a row of numbered cells with a pointer on one of them. Eight commands move the pointer, change the cell under it, read and print one character, and repeat a piece of program while that cell is not zero. Every other character in a program is a comment. The whole original definition is one table and three sentences [1]; what it leaves open is on the page Where implementations differ.

The machine

The program below is +++>++: six commands. Under it is a row of six cells that all hold 0, and a mark on the cell the pointer is on. Press Play, or drag Step forwards and backwards, and watch the marked command and the marked cell:

Three steps added one to cell 0, three times. The fourth moved the pointer to cell 1. The last two added one to cell 1. Nothing else happened, and nothing else can: a command either moves the pointer by one cell or works on the cell under it. The marked command is one place in the program, the marked cell is one place on the row, and nothing else is remembered. I'm showing six cells; the original has 30,000.

The parts have names:

Tape
The memory: one row of cells. The original has 30,000 of them [1]. Other implementations have more.
Cell
One place on the tape. It holds a whole number and starts at 0. In most implementations it holds 0 to 255, one byte.
Pointer
The mark that says which cell is the current one. It starts on the first cell. On these pages the first cell is cell 0.
Program
A text. The machine reads it from left to right, one command at a time, and stops after the last one.

The program had only two kinds of command. What can the other kinds do?

Notice what each one touched. + and - changed the cell under the pointer by one. > and < changed nothing on the tape, only the place of the pointer. . sent a cell to the output and , took a letter from the input. The pair [ and ] asked whether the cell was 0, and repeated what stands between them until it was. The commands come in four pairs. The two in each pair undo or complete each other: the first two pairs change the machine, the third makes a loop, the last speaks to the outside world.

  • ><Move the pointer> one cell right, < one cell leftchanges the machine
  • +-Change a number+ adds one to the current cell, - takes one offchanges the machine
  • []Make a loop[ and ] repeat what is between them while the current cell is not 0repeats and decides
  • .,Speak to the outside world. prints one character, , reads oneoutput and input

Four commands change the machine: two move the pointer, two change a number. Two speak to the outside world. Two make a loop. There are no names, no numbers written out, no "if", no functions. Whatever a program needs, it builds from these.

Order of the table. The README lists the commands in this order: the four that change the machine, then the loop, then output and input. Other texts often start with > and <.

The C column is the most exact part of the definition. It shows that a loop is a plain "while": test the cell, run the body, test again.

A loop repeats. What exactly decides when it stops?

Loops

The program below puts a number in cell 0, then runs a loop that takes 1 off cell 0 and adds 2 to cell 1, until cell 0 is empty. Press Play, or drag Step, and change the two sliders:

With the sliders as they were, cell 0 counted down from 3 to 0, and every round added 2 to cell 1. When cell 0 reached 0 the loop ended. Three times two is six: this loop multiplies. The part between [ and ] is the body of the loop. Slide the left cell to 0 and play again: the whole body is skipped.

Exactly:

  • At [ the machine looks at the current cell. If it is 0, the machine skips the whole loop and goes on after the matching ]. So a loop can run zero times.
  • At ] the machine looks at the current cell again. If it is not 0, it goes back to the start of the body.

"The current cell" is wherever the pointer is at that moment. The body may move the pointer, so the test at ] can look at a different cell than the test at [. The tape below starts with some cells that hold 1, followed by a 0, and the program is only [>]. Slide the number of 1s and press Play:

The pointer walked right, one cell for every round, and stopped on the first cell that held 0. Whatever the number of 1s, the program is the same. That is what [>] is for: it finds the next empty cell.

Brackets pair up like brackets in arithmetic, and loops can sit inside loops. In the program below the outer loop counts down cell 0. Each round it puts the number of the lower slider in cell 1, and the inner loop moves that number to cell 2. Choose both numbers:

Cell 2 ends at the product of the two numbers. Each ] belongs to the nearest [ before it that has no partner yet, so the inner loop ran to its end once for every round of the outer one. Cells 0 and 1 are empty afterwards: a loop reads a cell by counting it down.

Some implementations make ] jump back to the [ without looking, and let the [ do the test. The result is always the same. Only the number of steps differs.

A loop is also the only way to decide something. "If the cell is not 0, do this once" is a loop whose body ends by making the cell 0. The pattern If non-zero shows this, and the patterns section has many more.

So far the cells only held numbers. How does a number become a letter on the screen?

Output and input

The program below makes 64 with a loop (eight times eight), adds the number of plus signs you choose, and prints cell 1. Press Play and watch the line "Printed". Then slide the last number until it prints B:

With one plus sign the cell held 65, and 65 is the code of the letter A; with two it held 66, and B came out. The machine knows no letters, only numbers. The command . sends the number in the current cell to the output, and the screen shows the character with that code. The codes are those of the ASCII table: 65 is A, 97 is a, 48 is the digit 0, 32 is a space and 10 is a new line.

Now the other way. The program is ,+.: read a character, add one, print it. Type a letter in the box and press Play:

The command , took the next character of the input and stored its code, so the cell held the code of your letter before the +. Each , takes one character; a second , takes the next one. A digit you type arrives as its code too: the key 7 gives 55, not 7. A program that wants to calculate with it takes 48 off first.

Input and output are single streams of characters. A brainfuck program cannot open a file, draw on the screen or ask the time. It reads characters and prints characters. What happens when the input has run out is not defined by the original and differs between implementations: see the end of the input.

What a program is

A program is any text. The machine looks only at the eight command characters. The README: "All other characters are ignored." [1] So letters, spaces and line breaks can be used freely to lay a program out and to explain it.

++++++++        eight in cell 0
[ > ++++++++ < - ]   times eight into cell 1
> + .           one more makes 65 and prints A

This is the program of the printing figure with comments. Two things go wrong often:

  • Punctuation in a comment is a command. A full stop, a comma, a hyphen or a plus sign in your explanation will be carried out. The comments in the listing before this list avoid them on purpose.
  • Brackets must match. A [ without its ] has no meaning. The original compiler did not check this: "they better be", says the README [1]. The original interpreter stops with the message "UNBALANCED BRACKETS" [1]. What a given implementation does varies.

A common trick uses the first rule of Loops: a loop can run zero times. The first cell is 0 when a program starts, so a loop at the very beginning never runs. Text inside it is safe, punctuation and all, as long as its own brackets match:

[ This program prints A. Nothing in here runs, not even this: +++ . ]
++++++++[>++++++++<-]>+.

Programs are usually kept in files that end in .b (as in the original distribution [1]) or .bf.

What the original defines

The whole definition in the 1993 distribution is the table of commands (the table above gives its wording) and these three sentences [1]:

So the original fixes these things:

  • the eight commands and their meaning, by translation into C;
  • that other characters are ignored;
  • that there are 30,000 cells and that they, and the pointer, start at zero.

Elsewhere the README adds that the compiler of this version "operates on a byte array": a cell is one byte [1]. It says nothing about what happens when a cell goes past its largest value, when the pointer leaves the tape, or when the input ends. Those gaps are the reason two correct implementations can disagree. The next page of this reference, Where implementations differ, takes them one by one.

Is that claim true? "Every solvable mathematical problem" is the claim that the language is Turing complete. It is, with the proviso the README itself makes. See Theory.

There is no later official definition. The author has said so himself: the language has no formal standard, and people disagree about the size of a cell and about the end of the input [2]. What exists are careful descriptions by others [3] [4] [5].

Limits

  • The machines in the figures have cells of 0 to 255 that go round, a short tape whose ends are checked, and store 0 when the input has run out. Those are common choices, not the definition.
  • We describe the second version of the original distribution, the only one we found. See History.
